# Навыки для разработки бренд-протокола

Установлены 1 ноября 2026 года в `.agents/skills/` внутри рабочей копии проекта. Первым установлен `find-skills` командой `npx skills add vercel-labs/skills --skill find-skills --agent codex -y`. Затем по его инструкции проверены каталог skills.sh, результаты поиска CLI, источники и содержание кандидатов. Для установки использованы `skills@1.7.4` и временный локальный Node.js 22.23.4.

Комплект выбран для текущей стадии: подготовка одной услуги нутрициолога, проверка аудитории, завершение бренд-протокола и статического сайта. Его применение следует [ТЗ](TECHNICAL_SPEC.md) и [плану внедрения](IMPLEMENTATION_PLAN.md).

Для подключения новых навыков в каталоге Codex перезапустите сессию. [Документация Codex](https://learn.chatgpt.com/docs/build-skills) описывает обнаружение навыков в `.agents/skills/` проекта.

## Как применять к нашему проекту

1. Сначала прочитать [аудит](PROJECT_AUDIT.md), ТЗ и план. Использовать уже найденные сведения; вопросы нужны только по отсутствующим вводным.
2. Через `product-marketing` подготовить `.agents/product-marketing.md` на основании источников проекта. Этот будущий документ — краткий общий контекст для остальных маркетинговых навыков. Неподтверждённые сведения отметить как гипотезы или открытые вопросы. Сейчас документ ещё не создан.
3. Через `customer-research` подготовить интервью и затем разобрать полученные ответы. После проверки аудитории уточнить общий контекст и предложение услуги.
4. Через `content-strategy` и `copywriting` подготовить первый комплект материалов в объёме BP09 и тексты сайта. Учитывать время специалиста, утверждённую услугу и реальные доказательства.
5. При выполнении BP08 использовать `web-design-guidelines` для проверки интерфейса и `webapp-testing` для сценариев приёмки. Записывать фактически выполненные проверки и ограничения.
6. Применять `seo-audit` на этапе WEB05. Приватность и `noindex` до допуска к выпуску соответствуют текущему плану; сами по себе они не являются ошибкой черновика.

Инструкции пользователя и дизайн-контракт проекта имеют приоритет над общими примерами навыков. Для интерфейса сохраняются существующие цвета, типографика и компоненты из `nutrition-site/dist/styles.css` и решений проекта. Примеры SaaS, больших команд, платной рекламы и массового контента не определяют объём нашей разработки.

Все собственные материалы и отчёты ведутся на русском языке. Исходные файлы сторонних навыков оставлены без перевода и изменений для проверки происхождения и обновления. Примеры цифр, отзывов и результатов в них нельзя выдавать за сведения о нашей практике. Исследования не заменяют подтверждение квалификации, а маркетинговые формулировки не подтверждают медицинские обещания. Сырые клиентские сведения в репозиторий не помещаются.

Установка навыков не означает разрешения на рассылку, публикацию, изменение доступов или подключение платных сервисов. Эти действия выполняются в рамках конкретного поручения пользователя.

## Зависимости и пределы проверки

Большинство навыков — инструкции и справочные материалы. Для их чтения отдельный сервер или пакет npm не требуется.

- `webapp-testing` содержит четыре Python-файла. Справка `scripts/with_server.py --help` запускается. Примеры навыка рассчитаны на Python, пакет `playwright` для Python в этой среде отсутствует. Проверочный набор проекта использует вариант для Node.js, описанный ниже; установка самого навыка не добавляет браузерные зависимости.
- Дополнение после установки навыков: для [браузерной проверки](BROWSER_AUDIT.md) подготовлены Playwright для Node.js, Chromium и Firefox в `qa/browser/` и `.cache/browser-check/`. Python-пакет для этих сценариев не требуется. Запуск сайта закреплён в `.vibeforge/workspace.json`, подготовка тестовых инструментов — в `qa/browser/setup.sh`.
- Примеры `webapp-testing` содержат чужие порты и пути `/tmp` и `/mnt/user-data`. Их следует адаптировать: серверу назначать порт `VIBEFORGE_SESSION_PORT` / `PORT`, результаты сохранять внутри рабочей копии. Для пользовательского превью используется механизм VibeForge. Примеры нельзя запускать без подстановки среды проекта.
- `web-design-guidelines` при проверке загружает [актуальные рекомендации Vercel](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md), поэтому ему нужна сеть. Это рекомендации по качеству интерфейса; визуальные решения берутся из нашего проекта.
- Данные Search Console, статистика посещений и результаты интервью не появляются от установки навыков. В `seo-audit` применяются только проверки, для которых есть доступные данные; изменчивые требования проверяются по первичным источникам.

В этой работе проверена установка навыков. Новые браузерные тесты сайта, интервью и подготовка самого бренд-протокола не выполнялись.

## Обслуживание комплекта

Восемь каталогов и `skills-lock.json` хранятся вместе с проектом. Глобальная установка `-g` не используется. Временные загрузки, Node.js и кэш установки удалены после проверки; `.cache/skills/` исключён из Git.

Для повторного запуска CLI из корня рабочей копии нужен Node.js не ниже 22.20. В среде с Node.js 20 можно подготовить локальную версию, сохранив все записи внутри проекта:

```bash
mkdir -p .cache/skills/tmp
export npm_config_cache="$PWD/.cache/skills/npm"
export npm_config_update_notifier=false
export TMPDIR="$PWD/.cache/skills/tmp"
export XDG_STATE_HOME="$PWD/.cache/skills/state"
export DISABLE_TELEMETRY=1
npm install --prefix .cache/skills/runtime --no-save --no-package-lock --no-audit --no-fund node@22.23.4
export PATH="$PWD/.cache/skills/runtime/node_modules/.bin:$PATH"
npx --yes skills@1.7.4 list --agent codex
npx --yes skills@1.7.4 find 'customer research'
```

Добавление выбранного навыка: `npx --yes skills@1.7.4 add owner/repo --skill skill-name --agent codex -y`. Для восстановления проверенной версии вместо `owner/repo` можно передать GitHub-ссылку вида `https://github.com/owner/repo/tree/REVISION/skills/skill-name`, используя ревизию из таблицы выше. Новые версии сначала проверяются по содержанию и зависимостям; после обновления сверяются изменения навыков и `skills-lock.json`.

Внешних символьных ссылок нет. Пересчитанные SHA-256 каталогов совпали со всеми восемью записями `skills-lock.json`; `npx skills list --agent codex` обнаружил весь комплект. Проверка не является испытанием всех рекомендаций или полной проверкой безопасности стороннего кода.
