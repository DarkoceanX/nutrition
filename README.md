# «В своём ритме» — сайт консультаций по питанию

Статический сайт на HTML, CSS и JavaScript. Сборка и установка зависимостей не требуются.

## Аудит и дальнейшая разработка

По состоянию на 1 ноября 2026 года есть стратегия и приватный прототип сайта. Для запуска практики предстоит подтвердить сведения о специалисте, аудиторию, состав услуги, условия и клиентский процесс.

- [Аудит проекта](docs/PROJECT_AUDIT.md) — состав материалов, цели, стадия, подтверждённые проверки и обнаруженные пробелы.
- [Техническое задание](docs/TECHNICAL_SPEC.md) — пошаговые требования к бренд-протоколу, сайту и приёмке.
- [План разработки и внедрения](docs/IMPLEMENTATION_PLAN.md) — зависимости, роли, оценки трудоёмкости, запуск и пилот.

ТЗ и план имеют статус версии 0.1 для согласования. Они описывают будущие работы; исходные документы и текущий сайт сохранены. До публичного запуска необходимо устранить отмеченные в аудите проблемы формы без JavaScript и настройки порта локального сервера.

## Локальный запуск

Понадобится установленный Node.js. Из корня репозитория:

```powershell
cd nutrition-site
node serve.mjs
```

Откройте http://127.0.0.1:4173. Для остановки нажмите `Ctrl+C` в терминале сервера.

## Структура проекта

- `nutrition-site/dist/` — файлы сайта и изображения; это исходные файлы готового статического сайта, они хранятся в Git.
- `nutrition-site/serve.mjs` — локальный сервер для просмотра.
- `nutrition-site/.openai/hosting.json` — конфигурация существующей публикации Sites.
- `nutrition-site/PROJECT-NOTES.txt` — решения по содержанию, дизайну и публикации.
- Документы `.docx` в корне — стратегия и бренд-протоколы.
- `review/` — текстовые версии документов, снимок сайта и сведения о предыдущей публикации.
- `nutrition-site-deploy.tar.gz` — сохранённый архив предыдущей публикации; актуальные изменения следует брать из `nutrition-site/dist/`.

## Проверка JavaScript

Из корня репозитория:

```powershell
node --check nutrition-site/dist/app.js
node --check nutrition-site/serve.mjs
```

Форма записи подготавливает письмо через `mailto:`. Посетитель отправляет его самостоятельно; сайт не отправляет письма и не бронирует время автоматически.

Загрузка в этот репозиторий сама по себе не публикует сайт через GitHub Pages и не меняет настройки доступа существующей публикации Sites.
