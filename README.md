# «В своём ритме» — сайт консультаций по питанию

Статический сайт на HTML, CSS и JavaScript. Сборка и установка зависимостей не требуются.

С 2 ноября 2026 года сайт содержит ровно шесть страниц по разделу 7 `nutrition_brand_strategy.docx`: Главная, Обо мне, Консультация, Материалы, Контакты и документы, Клуб. Применено выбранное компактное оформление с меньшим количеством декора.

- [План разработки и внедрения](docs/IMPLEMENTATION_PLAN.md) — зависимости, роли, оценки трудоёмкости, запуск и пилот.
- [План Telegram-бота и ведения группы](docs/TELEGRAM_PLAN.md) — запись на консультации, добровольное вступление, ИИ-помощник, согласование публикаций и темы первого месяца.
- [Навыки для работы над проектом](docs/SKILLS.md) — установленный комплект, назначение, связь с ТЗ и порядок обновления.

Пройдены 68 групп основной проверки и 16 групп проверки автономного архива. Для публичного запуска остаются подтверждение сведений о специалисте, условий услуги и заполнение материалов и документов.

## Локальный запуск

Понадобится установленный Node.js. В VibeForge запуск выполняется во вкладке «Результат» командой из `.vibeforge/workspace.json`. Из корня репозитория используется та же команда:

```bash
node nutrition-site/serve.mjs
```

Порт передаётся окружением: сначала `VIBEFORGE_SESSION_PORT`, затем `PORT`. При отсутствии или неверном значении сервер завершится с понятным сообщением. По умолчанию слушает `0.0.0.0` для превью; адрес можно задать через `HOST`. Файлы определяются относительно `serve.mjs`.

Прямой адрес текущей серверной версии: [открыть сайт на сервере](http://199.195.196.219:5601/). Собственный домен для этого не нужен. 1 ноября 2026 года после восстановления процесса превью владелец подтвердил: сайт по этому адресу снова открывается. Страница, стили, скрипт и изображения также проверены с сервера, содержимое совпадает с рабочей копией. Адрес действует, пока работает процесс превью; постоянное размещение с автоматическим восстановлением ещё не настроено.

Есть также [существующая приватная публикация Sites](https://nutrition-daily-rhythm.stonybox65.chatgpt.site). Sites подтвердил активную версию 1 и доступ только владельцу; может потребоваться вход в аккаунт владельца. Это отдельная публикация: изменения рабочей копии попадают в неё после развёртывания новой версии.

Для просмотра без подключения к серверу скачайте [автономный архив](review/site-preview.zip), распакуйте его и откройте `nutrition-preview/index.html`. В нём работают все шесть страниц, меню, FAQ и форма; ресурсы встроены. После изменения сайта пересоберите архив командой `node qa/browser/export-preview.mjs`. Прежний `review/interactive-preview.html` сохранён как снимок одностраничной версии от 1 ноября.

Прямой просмотр по внешнему адресу доступен. Работа встроенной вкладки «Результат» через SSH отдельно не подтверждена. История диагностики и параметры проброса записаны в [отчёте](docs/BROWSER_AUDIT.md).

## Структура проекта

- `nutrition-site/dist/` — файлы сайта и изображения; это исходные файлы готового статического сайта, они хранятся в Git.
- `nutrition-site/serve.mjs` — локальный сервер для просмотра.
- `nutrition-site/.openai/hosting.json` — конфигурация существующей публикации Sites.
- `nutrition-site/PROJECT-NOTES.txt` — решения по содержанию, дизайну и публикации.
- Документы `.docx` в корне — стратегия и бренд-протоколы.
- `review/` — текстовые версии документов, снимок сайта и сведения о предыдущей публикации.
- `.agents/skills/` — восемь локальных навыков Codex; источники и контрольные суммы записаны в `skills-lock.json`.
- `qa/browser/` — подготовка Playwright, браузерные сценарии и запись демонстрации; порядок повторения — в отчёте.
- `review/browser/` — результаты проверки, изображения и видеозаписи с тестовыми данными.
- `nutrition-site-deploy.tar.gz` — сохранённый архив предыдущей публикации; актуальные изменения следует брать из `nutrition-site/dist/`.

## Проверка JavaScript

Из корня репозитория:

```powershell
node --check nutrition-site/dist/app.js
node --check nutrition-site/serve.mjs
```

Форма записи подготавливает письмо через `mailto:`. Посетитель отправляет его самостоятельно; сайт не отправляет письма и не бронирует время автоматически.

Загрузка в этот репозиторий сама по себе не публикует сайт через GitHub Pages и не меняет настройки доступа существующей публикации Sites.
